Pre-dated fill: two screen options

The farm owner records work from earlier days, using the same voice-log system. No verification step. Every such record is clearly marked as filled later, by the owner. Screens are Marathi (as the farmer sees them); captions are English for the founder. Nothing here is built yet. Pick V-A or V-B.

Founder decision, 27 Nov (verbatim): "A - there should be separate pre dated fill up flow same but for pre fill same system will work but it will update the previous work but that doesn't require any verification or cross verification and it must flagged as pre dated took this input from owner"Confirmed in the pilot on 28 Nov. Owner only.

How a pre-dated record stays honest

  • Work date = the past day (the owner picked it). Entry time = the real moment he filled it (today). Both are kept and shown; neither replaces the other (doctrine P8: provenance over precision).
  • The band reads "आधीची नोंद · मालकाने भरली" with both dates. It is never shown as if recorded on the work day (P1: the farmer asserted this later; the record must not impersonate a same-day record).
  • No "मालकाकडून खात्री" (verified) stamp. Nobody checked it, so it is not shown as checked (P4/P5: no fake proof). "तपासणी लागत नाही" says why.
  • Later corrections follow P3: a correction states "was X, is now Y"; the band stays.
  • It is stored on the server like any log (P10: not only on the phone).

Who may use it, and limits CTO proposal, founder may change

  • Owner only (primary owner; co-owner only if he holds the confirm-records grant). Workers and mukadams see the record and the band. They never see the fill link or button.
  • How far back: 30 days. Never before the plot's start date. Never today (today uses the normal mic) and never a future day.
  • Same day twice: allowed; each fill is its own entry with its own filled-at time.
  • Mixed day: a day that already has a normal same-day record gets the pre-dated fill added beside it, not merged into it.
  • Server must enforce owner-only. Hiding the link is not enough (today the server only checks farm membership, see evidence below).

V-AStart from the plot page: "आधीचं काम भरा"

The link sits on the log flow's plot page, below the normal "आजचं काम सांगा" mic. It opens a past-date picker, then the normal mic page, then the result.

What changes in the app (V-A)

Phone:
  • New link on the plot page, shown to owner role only; new date-picker sheet (reuses the existing day-pick words and farm-day rules).
  • The mic page and result screen get the date strip and the band; the verify and confirm controls are hidden for this kind of entry.
  • Band shown on list rows, the day view and the log detail; worker view shows it read-only.
Server:
  • New field on the log: "entered later by owner" (a kind value plus the owner's id; entry time already exists as the created-at time). New database column and migration; sent through sync push, pull and the log DTO.
  • Create handler: if the kind is set, require the owner role, reject beyond 30 days or before plot start, and write no review events of its own kind (see the open point on status below).
  • Verification queues and "तपासायची" lists skip these entries; reports label them.

Why V-A may suit, and its weakness

  • One new tap on a screen he already uses daily. Smallest build.
  • He picks the date before he sees which days are empty, so he may fill a day that already has a record. Mitigation: the date sheet greys out days with records only if he wants to avoid doubles (proposal: show a small dot on filled days).
  • The link on the plot page is one more thing on the busiest screen. Kept small and dashed on purpose so it does not compete with today's mic.

V-BStart from पूर्ण शेतीचा आढावा: tap an empty day

The owner sees the week strip on the farm overview. A day with no record has a hollow dot. He taps it and presses "या दिवसाचं काम भरा". Same plot step, mic and result after that.

What changes in the app (V-B)

Phone:
  • Overview day strip gets three dot states: record, no record, filled later (amber). The existing day bar already steps over past days and has a date picker.
  • The existing "त्या दिवसाचं काम सांगा" button on a past day is replaced for owners by "या दिवसाचं काम भरा", and is removed for everyone else (see evidence: today it is open to every member).
  • Same band and no-verification result as V-A; the day card shows the band.
Server:
  • Same server change as V-A (new kind field, owner-only, limits, migration, sync, DTO).
  • Overview data: the day-understanding read must report "filled later" per day so the strip can colour the dot.

Why V-B may suit, and its weakness

  • He sees which days are missing before he fills. This fits the farm-overview habit and prevents doubles naturally.
  • The fill path is built on the page that already has the past-day button, so the date handling exists.
  • Only works well once he opens the overview. A farmer who never opens it will not find the fill. Larger build than V-A because the strip and read model change.

Recommendation

Build V-B, and add V-A's small link later if owners ask.

Reason: the owner's real problem is "which days did I miss?". V-B shows the gaps first, so it avoids double entries, and it reuses the overview's day bar and past-day button already in the code. V-A is quicker to build but asks him to remember dates from memory, and it adds a link to the plot page he uses every day, which the founder wants calm. Both need the same server work (new field, owner-only, limits), which is the bigger half of the job. If time before the 3 Dec APK is the deciding factor, V-A fits in less time.

Open point for the founder: what status does the record carry? Proposal: it is stored as settled (no queue, no verify button) but with its own marker, never the "मालकाकडून खात्री" stamp. Today an owner's own new log is stamped "self-attested at creation" (see evidence); a pre-dated entry must not reuse that stamp because it would claim the owner attested it on the day.
