State C — already understood, confirm only

The test every screen must pass (founder, verbatim)
“Where is ShramSafal asking me for something I already told it?”
This screen is the purest expression of that test. On State C the farmer has already stated the count, the names and the crew. So this screen asks him for exactly one thing he has not yet given: his agreement.

The hub — the hero is now a confirm, not a recorder

The farmer is not asked to talk: the mic hero is replaced by a lighter, quieter card that says everything is already understood and asks only to be opened.

What changed from State A, and why it is visible. In State A the hero is the shipped emerald gradient mic card with a heavy drop shadow (shadow-[0_16px_32px_-12px_rgba(5,150,105,0.65)]) — the loudest object on the screen, because it is asking for effort. Here it is white with a thin emerald ring and a flat card shadow: same footprint, same corner radius, same उघडा chip, a fraction of the visual weight. The ask is smaller, so the object is smaller. The icon is a check, not a mic — there is no doorway to a recorder anywhere on this screen, because there is nothing left to say. The हजेरी घ्या / आज कोण आलं tile is gone from this hub. It was the one surviving doorway back to “tell me who came today” — the exact re-ask this screen's own never-do list forbids. In State C the day's people are already understood, so a capture tile is not a shortcut, it is the app asking again for what it was already given. State A drops तपासा from its hub for the same reason; the grid simply carries the tiles that still have a job. The हजेरी वही tile stays live and openable on every state: gating capture never gates memory.

Why this is a statement, not a checklist. The green ✓ beside each name is the हजेरी वही’s own present cell (bg-emerald-50 text-emerald-700, lucide Check at 13px / stroke 3.2) — the exact mark the register uses to say आला. It is not a tick-box: it is already true, it is identical on every row, and nothing on this panel is unset. There is no per-person confirm to work through, because working through it would be re-stating what he already said. गणेश’s two chips are two preserved facts, not one derived number. रात्र and 3 तास sit side by side exactly as the founder ruled. They are never merged into 1.5 दिवस, never turned into a clock range, and never priced. शंकर is a person; his eight are an aggregate. Two distinct facts on two rows, so 12 can be read back as 3 named + शंकर + 8 accompanying without hiding him inside a count. The reading of his ambiguous sentence is shown, not asked. Under शंकर sit his own words and, beneath them, what ShramSafal took them to mean — spec D9.5’s sourceText + systemInterpretation, drawn where he can see both. D9.5 forbids resolving it by assumption and says confirmation is what settles it, so बरोबर accepts the reading and बदल करा corrects it. It is not a third button and not a question on top of the confirm.

English: the understood reading, editable here like every other row. Changing it to “eight in total, Shankar counted inside” is a correction on this screen — not a separate question stacked on top of the confirm.
Correcting is cheaper than re-stating — that is the whole design. Every row arrives with आला already selected, in the app’s own shipped three-way control (Attendance.tsx, आला / अर्धा / नाही). Doing nothing changes nothing. Removing a person is one tap on नाही. Fixing a shift is one tap on अर्धा. There is no “start again”, no re-recording, and no re-parse: the same understood draft is edited in place, and the save word is still बरोबर, so the flow has exactly one save event whether or not he changed anything. There is no question block on this screen any more. “शंकर आठ जण घेऊन आला” is genuinely two-way in Marathi (+8 others, or 8 including him), and spec D9.5 settles how to handle it: carry sourceText and systemInterpretation, do not resolve it by undocumented assumption, and let confirmation settle it. So the reading is shown beside his own words — on the confirm panel in frame 2, and again here while correcting — and बरोबर / बदल करा is what settles it. An amber एक गोष्ट स्पष्ट करा strip belongs to State D, where the day itself contradicts itself; borrowing it here turned a visible interpretation into a second, blocking ask. A headcount stepper would be wrong for the same reason: he never stated a total, he stated a crew.

Open — needs a founder ruling before this is built

  1. 1. The transcript line in frame 2 — keep it, or is silence-plus-बरोबर enough? It is drawn here because “where did these names come from?” is the first thing a suspicious owner asks. But it is also the one element on the panel that could read as the app re-presenting what he said. Deleting it is a one-line change.
  2. 2. Three strings are unwritten — the confirm hero headline, the “nothing is saved until बरोबर” footnote, and the correction screen’s title. English meanings are drawn in place; the Marathi is yours.
  3. 3. Can hour-facts be corrected in R1? गणेश’s रात्र / 3 तास chips are drawn with a chevron, i.e. tappable. If they are not editable in R1, the chevrons come off and the chips stay as read-only facts — but then a wrong hour count can only be fixed by speaking again, which is the thing this screen exists to avoid.

What this screen must never do

Check the rule, not only the picture. Any one of these appearing means State C has failed.

  • ✗ Never offer a mic, or ask him to speak the same people again. He already said who was there. There is no recorder on any of these three frames, and no doorway to one.
  • ✗ Never show a headcount stepper. The count is known (12). A −/+ counter would be the app asking for a number it was already given.
  • ✗ Never show an empty form. बदल करा opens a populated list with every control pre-set. A blank field on this path is a bug.
  • ✗ Never ask या 12 जणांमध्ये कोण होते? That is State A’s question and it is already answered here.
  • ✗ Never show a per-person confirm checklist. The green ✓ marks are statements of what is understood, not boxes to work through.
  • ✗ Never show a Work Log bucket, crop picker or plot picker. This screen answers WHO. The work, the crop and the plot came from the Main Log and are not re-asked.
  • ✗ Never re-parse. बदल करा edits the understood draft in place; it never throws it away and starts the parse over.
  • ✗ Never show money. No rate, no wage, no total, no ₹ anywhere. Money lives in the register.
  • ✗ Never show a clock range or derived day-arithmetic. No 7:00–11:00, no from/to picker, no 0.5 दिवस / 1.5 दिवस. रात्र and 3 तास stay two separate stated facts.
  • ✗ Never render an unknown as – or 0. A blank dashed cell means nobody said; – means he did not come. The eight accompanying workers are counted, never silently named.
  • ✗ Never hide the हजेरी वही. Gating capture must never gate memory — the register tile stays live in every state.
  • ✗ Never stack a separate question on top of the confirm. “शंकर आठ जण घेऊन आला” is shown with the reading ShramSafal took — spec D9.5 — and बरोबर / बदल करा settles it. एक गोष्ट स्पष्ट करा is State D’s instrument, not this screen’s.
  • ✗ Never auto-save. बरोबर is the only save event on this screen, on both frame 2 and frame 3.
